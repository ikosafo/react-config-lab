## Task 2: .env.example File Creation

The `.env.example` file serves as a template for developers to create their own `.env` files. It typically contains safe default values to avoid exposing sensitive information.  

### Contents of .env.example:
- ENV_VAR_1=default_value
- ENV_VAR_2=safe_default
- ENV_VAR_3=safe_default
- ENV_VAR_4=safe_default
- ENV_VAR_5=safe_default

The safe values were chosen to ensure that the project can be run locally without any sensitive data, allowing for ease of use by new developers.

## Task 3: Environment File Override Behavior

Environment variables can be overridden using different methods, and the following scenarios illustrate their behavior:

1. **Scenario A:** Local `.env` overrides settings in the `.env.example`.  
   - Result: Local settings take precedence.  

2. **Scenario B:** Environment variables set in the hosting environment override local `.env`.  
   - Result: Always use the environment's settings in deployment.  

3. **Verification Procedures:**
   - Create a simple app that logs the environment variables to verify which is being used.  
   - Test various combinations to ensure the expected behavior of overrides.

### Complete Setup Instructions for New Developers:
1. Clone the repository.  
2. Rename `.env.example` to `.env` and fill in your values.  
3. Install dependencies using `npm install` or `yarn install`.  
4. Run the application using `npm start` or `yarn start`.
